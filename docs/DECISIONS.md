# Decisions

Any deviation from `docs/SPEC.md`, with the reason.

| Date | § | Decision | Reason |
| --- | --- | --- | --- |
| 2026-09-29 | §9.3 | `llm_model` default changed from `gemini-2.0-flash` to `gemini-3.8-flash`. Added `llm_max_attempts`, `llm_backoff_base`, `llm_max_workers` to `SimConfig`, with exponential backoff + jitter and retryable/fatal error classification in `llm/client.py` (new `llm/_retry.py`). | The live validation run discovered `gemini-2.0-flash` had been retired (404, API points to the new name). Separately, the client retried immediately with no backoff, so a transient 503 failed both attempts in milliseconds; concurrency was lowered from 8 to 4 to reduce self-inflicted load. 404/401/403/invalid-key are now classified fatal (no retry, immediate fallback) since retrying a permanently broken model/key wastes wall-clock during a live demo. |
| 2026-09-29 | §9.5 | The full-Gemini S2 transcript could not be completed in one session: the free tier caps `gemini-3.8-flash` at 20 requests/day, and cumulative development testing plus two partial S2 runs exhausted it. | Documented honestly in §9.5 of `docs/PROJECT_REFERENCE.md` rather than presenting a synthetic transcript. Two genuine live responses were captured and kept (one cached and replayable, one observed but not preserved to disk before a cache reset). The fallback behaviour was validated against a real quota-exhaustion event, not a simulated one — every failed call degraded cleanly to `template` and the run completed. Re-running after the daily reset with a warm cache costs nothing further, since calls are cached by prompt hash. |
| 2026-09-29 | §11.1 | **Fixed an infinite `Report` livelock that paralysed 20% of games.** A crewmate now reports only a body whose death is not already public (`death_notices`). | §11.1 step 1 returned `Report` whenever a body was in the room, with no check that it had already been reported. Since all agents respawn in `cafeteria` (§6.2 step 11) and cafeteria is both the spawn room and a common kill site, corpses accumulate there and every crewmate re-reported the same body every tick forever, never falling through to tasks or movement. Measured: **4 of 20 seeds ended with 15+ ticks of total paralysis** (seed 9 drew at the 400-tick cap with no movement after t=93). Found by instrumenting `decide()`, not by review — the engine's rejection of the invalid action is filtered out of the event log, so the failure was visible only as an *absence* of events. A regression test now asserts no live game contains a 15+ tick run without `MOVE`/`ARRIVE`. |
| 2026-09-29 | §5 | Vent edges take the **minimum** of available costs when `allow_vents=True`. | `GraphView.neighbors()` used `setdefault`, so for the five pairs that are both corridor and vent the corridor weight (3–4) was inserted first and the 1-tick vent cost discarded. Most of the impostor mobility advantage — and the alibi ambiguity that depends on it — did not exist. Crewmates still see corridor weights. |
| 2026-09-29 | §8.2 | `config.planner` is now read; `astar_no_risk` sets the risk weight to zero. | The switch was **dead code** — never read anywhere in `src/`. It is one of the four ablations in the write-up and the one backing the "belief becomes geometry" claim, so it had to actually work rather than appear to. |
| 2026-09-29 | §9.4, §16 | Added `--deliberator {template,gemini}` to the CLI and demo, defaulting to `template`. | Scenarios previously force-stamped `deliberator="template"`, so §9's entire LLM layer was unreachable from any CLI path — the second half of "search handles space, the LLM handles people" could not be demonstrated. Default stays offline so no test or demo spends quota; `gemini` with no key logs one line and falls back. |
| 2026-09-29 | §10 | Voting threshold `theta_vote` enforced in `_sanitize` for **every** deliberator, not only the template one. | With `deliberator="gemini"` the model's vote was taken verbatim, so the documented skip rule silently did not apply. A voting rule is a property of the protocol, not of one implementation. |
| 2026-09-29 | §10.5 | With `ejection_reveals_role=False`, the meeting note no longer claims a role. | The note rendered `"impostor" if was_impostor else "crewmate"` against a `None`, writing *"X was ejected and was an crewmate"* — injecting a **fabricated fact** into every agent's notes and then into the LLM prompt. |
| 2026-09-29 | §9.2, §10.1 | The meeting transcript now grows **within** a round, so speaker N sees speakers 1..N−1. | It was frozen at round start, which made the RNG-shuffled speaking order inert and prevented any same-round reaction. §9.2 block 4 is "every statement already made this meeting, in order". This is also what lets one agent contradict another in the same round — the core of the S2 demo. |
| 2026-09-29 | §11.1 | Added an **emergency-button step** (§11.1 step 4) triggered by holding an unvoiced `kill`/`vent` note. **Known limitation: it almost never fires.** | Measured 0 button presses across 20 games *after* implementing it. The cause is a design interaction, not a bug: §11.2 step 1 has the impostor kill only when no non-partner occupant is *observed*, so kills are unwitnessed by construction and the trigger's precondition is near-unsatisfiable. Retained because it is correct when it does fire (a vent sighting) and costs nothing; the crew's practical route to a meeting remains body discovery. Revisiting the trigger would mean weakening impostor caution, which is a worse trade. |
| 2026-09-29 | §12.3 | The reactor protocol uses a **single shared `ReactorBoard` object** passed to all eight policies, rather than literal per-agent message objects. | The `Observation` is room-local and carries no structured broadcast channel. A shared public bulletin is what makes "every agent runs the same deterministic function over the same public messages" both true and directly testable — the test asserts all eight agents compute an identical assignment. **Wiring requirement:** exactly one board per game; per-agent boards degrade the protocol silently, with no exception raised. |
| 2026-09-29 | §11.2 | The impostor's "≥3 crewmates alive" gate and doors targeting approximate the global roster from locally-knowable information (own kills, witnessed kills, reported bodies). | `Observation` deliberately exposes no global alive-roster — that would leak hidden state and break the partial-observability guarantee (§7). Approximating from what the agent can actually know is the correct behaviour, not a shortcut. |
| 2026-09-29 | §0 | Seven modules run 203–288 lines against the "~200" guideline. Accepted. | `resolve.py`, `impostor.py`, `crewmate.py`, `reactor.py`, `telemetry.py`, `engine.py`, `observation.py`. Each is one coherent responsibility; splitting further would fragment logic across files and hurt the explainability that is this project's primary design goal. The guideline exists to prevent sprawl, not to force arbitrary cuts. |
| 2026-09-29 | §13 | Deadlock response implemented as a rising-edge reaction to `PROGRESS_STALL`. **This was the single highest-impact fix in the build.** | Before it, a 9-combination config sweep (`tasks_per_crewmate` × `kill_cooldown`, 20 seeds each) showed *every* setting driving games to the 400-tick cap with up to 20/20 draws — the unbroken shadowing standoff made all balance measurement meaningless. After: mean 108.4 ticks, 1.55 kills/game, winner split crew 9 / impostor 9 / draw 2, only 2/20 reaching the cap. Impostors went from 0 wins to parity. |
| 2026-09-29 | §6.2 | **Split movement around kills**: arrivals (step 3) → kills (step 4) → departures (step 5). Previously all movement resolved before kills. | Found by measurement, not review. With movement fully before kills, a `Move` puts an agent into transit instantly and transit agents cannot be killed — so a target escaped simply by deciding to walk. Crewmates move nearly every tick while working. Instrumented result: of **31 kill decisions with the target co-located at decision time, only 2 resolved**, giving 0.10 kills and 0.05 meetings per game across 20 seeds — no bodies, no meetings, no deduction, and the LLM layer would never have been exercised. Splitting movement means a target cannot dodge by choosing to leave: it is already caught, and departs only if it survives. Also keeps kill resolution consistent with the observation the killer decided from. |
| 2026-09-29 | §3 | Added `task_duration_noise` (1) and `p_body_visible_lights` (0.70) to `SimConfig`. | The v2 trim dropped `task_duration_noise`, which left `PROJECT_REFERENCE.md` §6 claiming task durations were a source of stochasticity when they were fixed — a false claim on a Presentation 1 slide. The 0.70 body-visibility figure was a module-level constant, violating §0's rule that every tunable lives in `SimConfig`. |
| 2026-09-29 | §7, §14.1 | **Perception is rolled once and shared** between the event log's `witnesses` field and each observer's `local_events`. | The first implementation rolled `p_miss_eff` twice independently, so the log could record `witnesses: ["green"]` while green's own notes contained no kill. The UI would have shown green as a witness who never mentions it, and S2's acceptance depends on green actually holding that note. Now one `frozenset` at resolution time, with a test asserting `KILL.witnesses`, `local_events` and generated notes name identical sets. |
| 2026-09-29 | §14.1 | Pinned the full per-event field schema, plus `task_bar` on every line and `grace` on `REVOKE`. | §14.1 originally listed only event *type* names, so ui-engineer had to guess field names and telemetry later built to different ones — a silent UI breakage discovered only at integration. The schema is now a binding contract between `sim/telemetry.py` and `ui/viewer.html`. |
| 2026-09-29 | §11.2 | Impostor routing uses `plain_cost_fn`; only crewmates use risk-weighted A\*. | §8.2 frames the risk term as a crewmate mechanism ("for crewmate `i`"), and the "belief becomes geometry" claim is about crewmates avoiding suspected impostors. An impostor has no reason to avoid itself. |
| 2026-09-29 | §10 | `MeetingProtocol` sanitizes every `Statement` (clamps suspicion, drops unknown/self ids, vetoes an impostor voting for its partner) and catches any `Deliberator` exception into `LLM_PARSE_FAIL` + template fallback. | Built at M2 rather than M3 so the demo-safety path exists before the Gemini client is plugged into the same seam. An LLM response must never be able to crash a run. |
| 2026-09-28 | all | **Replaced the v1 Bayesian design with the v2 minimal MVP spec** (`docs/SPEC.md`). v1 archived at `docs/archive/v1_bayesian_reference.md`, no longer authoritative. | The assessment rubric rewards none of the heavy machinery. Neither rubric mentions exact inference; the "Exceeds" bands name deadlock resolution, dynamic renegotiation, environmental shocks and informed search. The 28-hypothesis belief model, Held–Karp and the time-expanded DAG were three hard things to defend in Q&A for zero marks. Cutting them takes the build from ~4,000 lines to ~1,200 without losing a single rubric criterion. |
| 2026-09-28 | §9 | **LLM (Gemini Flash) replaces exact Bayesian belief** for social reasoning. | Exact inference requires a hand-specified likelihood per message type and assumes a known message-generating process — tractable only under a fixed schema. Natural-language testimony has an unbounded observation space, so no likelihood can be written down. Accepted cost: no correctness guarantee, no per-call determinism. Mitigated by seeding the world and caching every call by prompt hash. |
| 2026-09-28 | §0, §9 | **LLM calls confined to meetings**, never the tick loop. | Per-tick calls would be ~800 per game: minutes of latency, real cost, and a high chance of an invalid action mid-presentation. Meetings-only is ~40 calls, parallelised per agent. It also gives the clean architectural line "search handles space, the LLM handles people". |
| 2026-09-28 | §8 | **A\* is the production planner**, with BFS/Dijkstra/greedy kept only to generate the comparison table. | The P1 rubric names "informed search" explicitly. A\* also has a heuristic whose admissibility is derivable on a whiteboard in 30 seconds, which is what Q&A rewards. v1 had argued A\* was pointless on 14 nodes — true for raw performance, irrelevant to what is being marked. |
| 2026-09-28 | §11.1 | **Nearest-first task ordering instead of Held–Karp.** | With 4 task rooms the optimal tour saves a handful of ticks and costs a subset-DP recurrence to defend under questioning. Recorded as a judgement call, not an omission — the trade is stated on the P1 slide. |
| 2026-09-28 | §15, §19 | **Self-contained HTML replay viewer**, reversing v1's "no web UI" exclusion; a live web server stays out of scope. | Demo Quality is 3 marks and a canvas map with a meeting transcript is far more legible than terminal text. Replaying `events.jsonl` keeps the viewer fully decoupled from the simulator, so it cannot crash a live demo the way a websocket server could. |
| 2026-09-28 | §2 | **Mesa kept as a ~60-line wrapper**; matplotlib and pandas dropped. | The P2 rubric names Mesa as an industry-standard tool, and the wrapper is cheap. Plots are replaced by the HTML viewer, so matplotlib earns nothing. |
